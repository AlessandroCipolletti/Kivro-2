## Implementation sequence

1. Implement durable seller-local Worker state, restrictive file ownership, persistent emergency pause and audit events; a local pause must take effect before success is returned and survive restart.
2. Add persistent cryptographic device identity/pairing state without storing seller passwords or private keys in cloud metadata.
3. Extend read-only OpenClaw discovery and add pinned compatibility/readiness checks. Never treat detection as seller consent or execution readiness.
4. Add host-native Worker CLI (`doctor`, `health`, `pause`, `resume`, device/capability status) with sanitized output and fail-closed security checks.
5. Build the separate worker OpenClaw environment and execution adapter only with mandatory Docker sandbox policy; execute adversarial filesystem/network tests before remote dispatch. M04 owns the full sandbox implementation and parity proof.
6. Implement the M02 auth scope on one Kivro account model: map the selected auth library to the canonical account ID and PostgreSQL schema, implement email/password hashing and verification, durable email delivery, reset, rate limits, secure sessions, Google OIDC with identity-only scopes and verified-claim linking, then build conventional sign-in/verification/reset screens. Run database/API/browser tests, local email and Google callback tests, and a real Google non-production acceptance test when credentials are available. Do not call a pure linking decision or installed dependency an auth flow.

## Tests and risks

Required: local SQLite restart/pause/identity tests, permissions and no-secret tests, OpenClaw CLI compatibility fixtures, doctor critical-FAIL tests, sandbox denial tests, protocol replay/ownership tests, auth unit/integration/browser E2E and later both-profile conformance. Critical risks are personal OpenClaw leakage, host execution fallback, unauthenticated local management, insecure key storage, pause loss after crash, false health/readiness, and duplicate dispatch. No paid execution path may be enabled until payment, sandbox, authorization and durable job gates pass.

## Evidence from this increment

- `apps/worker/src/local-state.ts` stores pause state and append-only audit events in seller-local SQLite with restrictive permissions and full synchronous commits. Local pause, restart persistence, duplicate commands, security pause, capability pause, cloud-sync revision and pause/resume race checks are exercised by `tests/worker-local-state.test.mjs`.
- `apps/worker/src/cli.ts` and `tools/kivro-worker.mjs` provide `pause`, `resume`, `health --json` and `doctor --json`. `tests/worker-cli.test.mjs` tests pause across processes, fail-closed resume, sanitized diagnostics and an honest `NOT_READY` status.
- `apps/worker/src/device-identity.ts` creates persistent Ed25519 identities with an OS keychain primary adapter and an explicit encrypted-file fallback. `tests/device-identity.test.mjs` checks signing, keychain public-only metadata, wrong-passphrase rejection, private file permissions and fail-closed keychain outage using an in-memory vault. The native keychain was not modified during tests; live keychain integration, remote pairing, revocation and rotation remain open.
- `packages/openclaw-adapter/src/worker-environment.ts` creates separate private per-Worker home/config/state/workspace/skills directories with a deny-by-default Docker baseline that requires a digest-pinned image. `tests/worker-environment.test.mjs` checks isolation and forbidden-tool defaults. `pnpm test:openclaw:isolation` validated the generated JSON against installed OpenClaw 2026.8.2 using only the dedicated environment. This validates config syntax, not an effective sandbox or execution readiness.
- The live personal-state skill-list command was disabled after it attempted permission changes. `packages/openclaw-adapter/src/read-only-discovery.ts` now scans bounded JSON5 config and `SKILL.md` frontmatter through read-only filesystem calls, including verified installed bundled/Custodian roots. Findings have unknown readiness and no consent. Fixture tests prove unchanged bytes/modes/mtimes, symlink denial, uncertainty, dependency declarations and no secret/path leakage. `pnpm openclaw:inspect` found 57 file-backed candidates on installed 2026.8.2; a passing `pnpm test:openclaw:readonly-live` run found no mode/size/mtime/ctime change among 57,826 personal/package entries. One earlier run observed a same-count metadata change, likely concurrent personal-state activity. Authoritative Gateway inventory, seller selection and effective readiness remain open; see `docs/openclaw-interfaces.md` and `DEC-IMPL-001`.
- The `--version` child now runs in a temporary isolated home with no inherited seller secrets. `packages/openclaw-adapter/src/compatibility.ts` pins 2026.8.2 as a candidate, with `executionAllowed: false`; unknown versions fail closed. The doctor reports candidate status as a blocking FAIL. `tests/openclaw-compatibility.test.mjs` and version-probe isolation tests pass. See `DEC-IMPL-002`.
- `packages/domain/src/identity-linking.ts` adds canonical email and verified-Google-claim account-link decisions; `tests/identity-linking.test.mjs` covers same-account linking, unverified claims, conflicting subjects and alias preservation. Real signed Google OIDC callback and same-account database tests remain open.
- `apps/web/src/auth/options.ts` maps Better Auth's user and account records onto Kivro's `accounts` and `account_identities` tables. Forward-only migrations `0002`–`0006` add sessions, verification, database rate limits, encrypted email outbox and a server-side one-use verification-token registry. The registry closes a discovered library gap: its signed verification JWT otherwise remained reusable until expiry. `tests/auth-options.test.mjs`, `tests/auth-outbox.test.mjs`, `tests/auth-request-guard.test.mjs`, and `tests/sql/m02_auth.sql` cover the configuration and constraints. `pnpm test:postgres:m02` passed in disposable PostgreSQL 16.
- `apps/web/src/auth/password.ts` pins Argon2id v19 at 64 MiB/three passes/one lane with PHC strings and rejects malformed or downgraded hashes. Unit, local PostgreSQL/Mailpit, and Chrome E2E tests pass. `AUTH-004` has full evidence; see `DEC-IMPL-003`.
- A local Google OAuth initiation test uses a dummy non-production client ID and checks Better Auth's generated authorization URL: exactly `openid`, `email`, `profile`, no `include_granted_scopes`, the local callback URI, and a CSRF state value. Client-supplied scope/ID-token paths are rejected. This verifies `AUTH-009` without claiming a real Google callback or account-link acceptance.
