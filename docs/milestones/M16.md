## Verified component evidence and correction

`pnpm test:core-worker:m16` runs M13's disposable PostgreSQL/SeaweedFS fixture plus `tests/m16-core-worker-integration.mjs`. The second test account cannot read the buyer's result. A real pinned OpenClaw image runs in the Docker sandbox, reads the private input through the broker, generates text and a file, uploads via signed PUT, finalizes through the signed Worker RPC, returns the private file through authenticated REST, and creates exactly one `SETTLE` journal and one seller earning even after a duplicate finalization. `finance.reconcileLedger()` returns zero discrepancies. A second real Docker/OpenClaw run injects a model crash after execution starts and verifies `FAILED_EXECUTION`, reservation release, zero settlement journals and unchanged seller earnings. The fixture keeps the M13 API rate-limit probe on a separate account so the additional paid jobs do not consume its limit. A run with `KIVRO_M16_LIVE_CLAMAV_SOCKET=tcp://127.0.0.1:13310` used the pinned live ClamAV service and passed. `tests/m15-clamav-live.test.mjs` independently passed clean and EICAR scans after the daemon loaded its signatures.

The integration exposed an M05/M13 production defect: the signed PUT included `content-length` in its signature, but the returned header set omitted it. Buffer uploads worked because `fetch` inferred the length; the Worker file stream got HTTP 403. `packages/infrastructure/s3/src/storage.ts` now returns the signed `content-length` header and the real streaming path passes. The M16 fixture restores the original published version/heartbeat after its run to avoid altering the subsequent M13 scheduling assertions.

The slice does **not** use Stripe test-mode purchase, authenticated seller publication or the production host-native Worker loop. It does not close §§88–92 or any paid-release gate. The global release gate currently exits nonzero by design. This is an honest incomplete M16 boundary, not a completed milestone.
