## Concise implementation plan

1. Define a provider-neutral, immutable effective sandbox policy from a validated capability manifest and platform minimums. Reject browser/personal-session access, host mounts, elevated tools, unsigned/mismatched policy and any network need without a tested broker route.
2. Implement the Docker adapter behind a Worker-owned execution contract. Require a digest-pinned approved image, read-only root, no network, dropped capabilities, no-new-privileges, non-root user, restricted mounts and CPU/memory/PID/time limits. Missing Docker/image/policy must refuse execution; never fall back to host OpenClaw.
3. Build private per-attempt input/output directories and process supervision with deterministic timeout/kill/cleanup. M05 will supply validated asset staging/collection; M07 will bind signed paid offers and real OpenClaw execution.
4. Inspect the actual container configuration and run adversarial canaries for host files, personal OpenClaw, Docker socket, network, privilege, write paths, process escape and timeout. Keep initial sandbox offline until M06 brokers enforce narrow egress and provider cost limits.
5. Add the M04 operational security baseline: incident response, sanitized correlation/log contracts, environment/migration discipline, CI gates, global dispatch kill-switch design and exact internal permission diff/publish prerequisites.
6. Revisit M02/M03 deferred gates as each actual runtime dependency arrives. §§278–298 fixed price table has a pure Core baseline from M01; seller UI, ledger, taxes/processor policy, refunds and Agent quotes become eligible at M08/M10/M11/M14 and remain open meanwhile.

## Required validation

Publishing and paid dispatch remain disabled until their real prerequisites pass.

## Evidence and stage disposition

The provider-neutral offline policy rejects unapproved images and any network, inference, browser, seller resource, credential, tool or side-effect need without later brokers. The Docker adapter accepts only a digest-pinned approved image, inspects effective Docker settings before starting, uses one private read-only input mount and temporary filesystems, and refuses Docker/image/policy failures without a host fallback. The real local adversarial canary covers user/capability/no-new-privileges settings, root/input/host path denial, socket absence, network denial, timeout and cleanup. `docs/test-evidence/m04-sandbox.md` records the exact environment, command and limits. `docs/INCIDENT_RESPONSE.md` defines response for the four required incident classes; `.github/workflows/ci.yml` wires current tests to PRs, including the Docker canary. The pre-existing canonical price-tier Core and exact-reference permission diff are preserved.
