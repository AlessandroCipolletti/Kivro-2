# M05 private assets and storage evidence — 2026-10-06

The shared asset contract creates opaque `private/assets/<asset-id>/<random-id>` keys. A pure access decision admits a retained READY asset only for its owning buyer or a grant-bound, assigned, active Worker on a secured, active job. It does not authenticate callers by itself; M07 must resolve actor, job and grant from durable authoritative state.

Forward migrations `0010_private_assets.sql`–`0012_asset_retention_guards.sql` add private asset metadata and scoped job read grants. They constrain owner/source-job consistency, READY metadata, immutable finalized identity/hash, legal state changes and extension-only retention; grants require a READY asset and same-buyer target job, and revocation is one-way. `pnpm test:postgres:m05` passed against disposable PostgreSQL 16, including cross-buyer and mutation denials. `pnpm local:auth:migrate` applied all three migrations to the local development database.

The provider-neutral `ObjectStoragePort` has one S3-compatible adapter for Netsons storage, AWS S3 and local storage mechanics. The adapter uses private keys, short-lived signed PUT/GET URLs, signed content type/length/SHA-256 headers, private HEAD/read/delete and streaming server-side put. A disposable local MinIO integration passed server put/read, anonymous GET denial, signed GET, signature tampering denial, direct signed PUT, checksum tampering denial and deletion. `verifyStoredObject` in shared application code hashes the stored stream and rejects missing, truncated, oversized or hash-mismatched objects even if object metadata claims the expected digest; unit tests pass. AWS SDK packages are pinned to 3.1146.0. Fresh local Compose uses a pinned SeaweedFS image with an explicit private S3 identity; the cached MinIO fixture is an additional adapter test.

These tests do **not** provide an authenticated upload/download API, private bucket deployment policy, durable job finalization, automatic retention cleanup, browser history, or both-profile conformance. Presigned URLs are bearer capabilities; the application must authorize immediately before issue, never expose storage credentials, and verify uploaded bytes before an asset becomes READY. No paid result can be served from this increment.

The direct-upload validator now streams the stored object, compares HEAD length and actual bytes to the claimed size, hashes actual bytes, detects content type, requires its MIME and extension to be an allowed **pair**, validates UTF-8/JSON where applicable and rejects unknown/archive formats. `tests/input-object-validation.test.mjs` passes valid content, MIME disguise, bad digest, bad size and invalid JSON cases. No API yet transitions an asset to READY.

`DEC-IMPL-008` adds a bounded stopped-output path. `pnpm test:sandbox:output` passed a real Docker job container with only a private read-only input mount and size-limited non-root tmpfs output volume, a separately inspected read-only collector, streamed bounded tar extraction, stopped-result contract validation and full job/collector/volume/staging cleanup. It also rejected symlink output and a 100 MB sparse file under a 4 KB logical output limit. `pnpm test:output:storage` passed the real Docker path into disposable private MinIO: the Worker streamed the selected file, verified the stored object's size/hash, produced a job-scoped asset manifest, removed local staging and proved anonymous GET was denied while a signed GET returned exact bytes. It then used the short-lived signed GET to stream the same asset into a private Worker attempt, validated hash/type/size again, mounted it read-only in another offline Docker job and removed the input staging. These tests use an Alpine fixture; pinned OpenClaw execution and authoritative cloud job finalization remain OPEN.

Forward migration `0012_asset_retention_guards.sql` prevents shrinking finalized asset retention and blocks a job grant that would outlive the asset. The disposable PostgreSQL suite passed both denials. M07 must extend retention before scheduling or granting a long-running job and provide a retryable object-deletion sweep after terminal/expiry policy permits it. The pure I/O compatibility and fixed instruction-envelope tests pass, but no Agent planner or live OpenClaw consumer uses them yet.

`pnpm test:storage:seaweedfs` passed against a pinned, remotely pullable SeaweedFS 4.48 digest with an explicit private S3 identity. It proved anonymous GET denial, signed GET and PUT, stored length and rejection of changed bytes under a signed checksum. `pnpm local:auth:up` prepares a private identity file, starts the pinned storage service through Compose, creates the bucket and checks anonymous denial; its idempotent local run passed again during the focused M05 review. The cached MinIO integration remains an additional adapter fixture. CI includes the pullable SeaweedFS test; hosted CI itself has not yet run.
