# OpenClaw discovery interface

Kivro detects the installed version with `openclaw --version` under a fresh temporary HOME/state/config directory and a minimal environment; that directory is removed after the child exits. On OpenClaw 2026.8.2, `openclaw skills list --json` attempted permission hardening in the seller's personal state. `openclaw config validate --json` is also withheld from live personal-state inspection because its read-only behavior has not been proven. The command runner allowlists only `--version` and still enforces a deadline and output cap.

`ReadOnlyOpenClawDiscovery` in `packages/openclaw-adapter` is the live discovery path. It uses read-only filesystem operations to parse bounded JSON5 config and YAML `SKILL.md` frontmatter. It scans the documented workspace, project, personal, managed, and configured extra skill roots. It also resolves the installed executable link without running it, verifies the adjacent `package.json` identifies OpenClaw, and scans its bundled and Custodian skill roots. It extracts agent IDs, declared model and tool references, plugin names, and declared skill binary/environment/config requirements. It never opens `.env`, credential files, or OpenClaw databases and never executes skill bodies. The config is parsed in local memory, so it may contain secrets, but paths, descriptions, config values, and secret values are omitted from the discovery result. `pnpm openclaw:inspect` prints a sanitized count/status report.

Every finding is a **candidate**. Skill readiness and visibility are `unknown`, all consent is `not-granted`, and tool/plugin/model entries are only configured references. File metadata cannot establish the authoritative Gateway inventory, effective eligibility, runtime compatibility, or permission grants. The scanner reports unresolved `$include`, malformed metadata, symlinks, collisions, inaccessible roots, and scan limits as explicit issues. Symlinks and roots outside the seller home are skipped; this can make discovery incomplete. Bundled, plugin-provided, workshop, node-hosted, and database-backed skills are not yet inventoried by this path. Seller selection and deterministic readiness are separate later steps.

`tests/openclaw-discovery.test.mjs` checks normalized candidates, declared dependencies, no consent, no secret/path leakage, symlink denial, uncertainty, unchanged fixture bytes/modes/mtimes in both seller and installed-package roots, package identity rejection, and version-probe isolation. A live OpenClaw 2026.8.2 smoke test on 2026-10-06 detected version from a temporary home and parsed personal config plus installed package metadata with 57 file-backed skill candidates, five plugin references, and no reported scanner issues. `pnpm test:openclaw:readonly-live` also passed a before/after mode, size, mtime, and ctime snapshot of 57,826 personal/package entries. Its first attempt detected a same-count metadata change, likely from concurrently active personal OpenClaw state; a second attempt was unchanged. Fixture tests prove byte integrity for controlled roots. These tests do not establish authoritative Gateway inventory or effective skill readiness. Seller selection and runtime gates remain open in `docs/verification-backlog.md`.
