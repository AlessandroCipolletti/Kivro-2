# Kivro

Kivro is a greenfield marketplace for narrowly scoped, seller-hosted OpenClaw capabilities. The authoritative product and engineering specification is in [`spec/`](spec/MASTER-SPEC.md).

## Current state

The repository contains component implementations through M15 and ongoing M16 verification. The installed two-account Stripe-funded buyer-to-Worker path, both-provider conformance and final release gates remain open. `pnpm release:gate` fails closed while mandatory requirements or evidence are missing. See [`docs/implementation-status.md`](docs/implementation-status.md), [`docs/milestones/M16.md`](docs/milestones/M16.md) and [`docs/verification-backlog.md`](docs/verification-backlog.md) for current evidence and gaps.

Run `pnpm install`, then `pnpm typecheck`, `pnpm lint` and `pnpm test`. `pnpm openclaw:inspect` uses a read-only filesystem scanner for bounded local config and file-backed skill metadata; its sanitized result remains advisory, with unknown readiness and no seller consent. Stateful personal config/skill CLI commands stay disabled. `pnpm worker health --json` reports the current local state, and `pnpm worker pause --all` durably pauses new work locally.

`pnpm test:postgres:m01` runs the first migration and constraint checks in a disposable, port-free PostgreSQL 16 Docker container. It requires a local Docker daemon and image.

`pnpm test:openclaw:isolation` validates the generated dedicated Worker config against a locally installed OpenClaw CLI. It runs OpenClaw with isolated temporary home/state/config paths and does not read the seller's personal OpenClaw profile.

For the M02 authentication path, run `pnpm local:auth:up`, then `pnpm local:auth:migrate`, then `pnpm test:auth:local` and `pnpm test:auth:browser`. Setup writes private `.env.local` once and starts loopback-only PostgreSQL and Mailpit. [`.env.example`](.env.example) explains each setting and contains deliberately unusable secret placeholders; use the generated `.env.local` for local development. The backend and Chrome browser tests exercise real email registration, verification, login, reset, logout and SMTP delivery; they do not require Google credentials. The browser test uses local port 3335 and the installed Chrome on macOS. Mailpit is available at `http://127.0.0.1:18025`. `pnpm local:auth:mail --once` drains queued auth messages. The Worker and web app remain host-native; this Compose file supplies auth infrastructure only.

For M03 seller entry, `pnpm test:seller:local` checks one seller profile per verified account, concurrency and the append-only execution-model acknowledgement against the local PostgreSQL database. `pnpm test:postgres:m03` checks visibility, private grants, lifecycle and acknowledgement constraints in a disposable database. The browser auth test also creates a draft seller profile after explicit acknowledgement.

Production seller enrollment is private-alpha invitation-only while the §91 public security gate is open. A database administrator can issue or revoke an account-bound invite with `DATABASE_URL=... pnpm seller:invite grant ACCOUNT_UUID [HOURS]` or `DATABASE_URL=... pnpm seller:invite revoke ACCOUNT_UUID`. The account must already be active and verified. The invite is consumed atomically on first profile creation, and every grant, revoke and consumption is audited. There is no production public-enrollment switch. `pnpm test:postgres:m14-publication` exercises denial, expiry, revocation, concurrency and HTTP retry.

`pnpm test:sandbox:docker` runs the M04 real Docker isolation canary using a cached, digest-pinned Alpine fixture. It checks effective container settings, host-path/socket/network/root/input denial, non-root privileges, timeout, cleanup and fail-closed missing prerequisites. The pinned OpenClaw image has its separate M07 execution suite. See [`docs/test-evidence/m04-sandbox.md`](docs/test-evidence/m04-sandbox.md).

For M05, `pnpm local:auth:up` starts PostgreSQL, mail and a private S3-compatible SeaweedFS service on loopback, creates the bucket and checks anonymous access is denied. `pnpm test:postgres:m05` runs asset/grant constraints; `pnpm test:storage:seaweedfs` checks the pinned, pullable local storage image; `pnpm test:storage:minio` remains an optional second adapter check using a cached MinIO image. `pnpm test:sandbox:output` tests size-limited stopped-output transfer, and `pnpm test:output:storage` runs the real bidirectional Docker ↔ private storage path.

For M06, `pnpm test:postgres:m06` runs broker usage, read-only resource and provider-budget checks in a disposable PostgreSQL container. `pnpm test:research:live` makes one bounded pinned HTTPS GET to `example.com`; it needs outbound DNS/HTTPS. The Brave search adapter is tested with fixtures; a real platform token is not configured by local setup. [`.env.example`](.env.example) describes `KIVRO_BRAVE_SEARCH_TOKEN` for the later cloud composition root. See [`docs/milestones/M06.md`](docs/milestones/M06.md) for evidence and deferred gates.

For M07–M09, run `pnpm test:postgres:m07`, `pnpm test:postgres:m08`, `pnpm test:postgres:m09` and `pnpm test:openclaw:execution`. These exercise durable execution, exact credit/ledger transitions, availability/queue races and the pinned Docker/OpenClaw image. `pnpm scheduler` runs host-native M09 reconciliation and M16 paid dispatch against `DATABASE_URL`; set `KIVRO_STRIPE_MODE`, `KIVRO_CONTROL_PLANE_ID` and `KIVRO_CONTROL_PLANE_STATE=ACTIVE` to match the Web/API process. A DRAINING scheduler continues maintenance but issues no new leases. Optionally tune `KIVRO_SCHEDULER_INTERVAL_MS`. In local development run the scheduler in its own terminal alongside the web app and Worker. It also records one seller-only availability observation per published capability per minute; missed periods remain unknown. `node tools/kivro-scheduler.mjs --once` performs one bounded sweep after `pnpm build`. Deployment scheduling in Netsons and AWS remains an M19 task.

The guided Worker import can select a discovered loopback OpenAI-compatible local model or a dedicated remote provider. Discovery only reads OpenClaw metadata; every model and dependency still needs seller selection and the real isolated review. The local model is reached through the host-side broker while Docker remains offline, and missing model health blocks new offers. `pnpm test:openclaw:execution` includes a real pinned Docker/OpenClaw local-model job plus PID and memory cgroup probes. `pnpm test:resource:e2e` runs a separate synthetic read-only PostgreSQL resource through the real Worker broker and Docker/OpenClaw, denying an undeclared table and writes. These are component evidence, not the paid Stripe E2E.

`pnpm test:e2e:local` now runs a disposable two-account development-payment path through authenticated seller Web publication, buyer Web input upload and quote, buyer REST purchase, the host-native Worker, scheduler, pinned Docker/OpenClaw, private object storage, authenticated result/download and one ledger settlement. It also exercises Worker restart, a lost finalization acknowledgement and durable replay, duplicate requests/finalization, cancellation, model and output-storage failure with credit release, and live paid-sandbox host/network denial. Development credits are allowed only outside production; this command does **not** prove a Stripe purchase, a supported Worker installer or the entire 44-step staging sequence. `pnpm test:e2e:local:stripe` uses the same Worker harness with a real Stripe test PaymentIntent and an existing ready test Connect account; it fails before creating infrastructure when the test credentials named in [`.env.example`](.env.example) are absent. `pnpm test:e2e:local:preflight` remains a separate environment check.

The Worker can use signed polling or WSS behind one protocol contract. During a backend transition it keeps an owned old job on its old plane, accepts new work only from the active plane, and restores an old draining route from private local state after restart. `pnpm worker:wss` starts the dedicated WSS control endpoint when configured with TLS; loopback cleartext is allowed only outside production.

On macOS private-alpha machines, `pnpm worker:service install` followed by
`pnpm worker:service start` runs the same host-native Worker under a per-user
LaunchAgent across login and process restart. Build and pair the Worker first;
see [the Worker installation instructions](apps/worker/README.md). The
LaunchAgent references a private `.env.local` and a built checkout, so it is
reinstalled after moving the checkout. Signed public updates remain a separate
pre-launch gate.

For M10–M11, run `pnpm test:postgres:m10`, `pnpm test:postgres:m11` and `pnpm test:browser:m10`. The browser suite exercises the real buyer pages, persistent Agent plan review, approval/cancellation and private storage with disposable infrastructure; its inference fixture is deterministic. Configure an OpenAI or Anthropic **platform** API key and matching model in the ignored `.env.local` to use AI Request interactively. The keys stay in the Web/API process. Without a valid provider, Discover and the rest of the classic marketplace remain usable while AI Request reports unavailable. `pnpm local:agent:setup` adds a private Agent reconcile token to an existing `.env.local` once; fresh `pnpm local:auth:setup` files already contain one. Run `pnpm agent:scheduler` in its own terminal to advance approved plans after browser closure or Web/API restart. It calls only the loopback Web/API endpoint with that token and retries transient outages. `node --env-file=.env.local tools/kivro-agent-scheduler.mjs --once` runs one sweep. Production scheduling and managed platform secrets remain M19 gates; live provider contracts require non-production provider credentials. See [`docs/milestones/M11.md`](docs/milestones/M11.md).

Run `pnpm --filter @kivro/web dev` for the local web UI after setup. The setup command links the web app to the ignored local environment file. Start `pnpm local:auth:mail --watch` in another terminal to deliver verification and reset messages while using the UI.

For M13 buyer integrations, `pnpm local:webhooks:setup` adds private webhook keys to an existing `.env.local`; a fresh local setup includes them automatically. Run `node --env-file=.env.local tools/kivro-webhook-dispatch.mjs` in another terminal to deliver signed events after browser closure or process restart (`--once` makes one bounded sweep). `pnpm test:postgres:m13` and `pnpm test:browser:m13` use disposable PostgreSQL and Mailpit. See [`docs/API-v1.md`](docs/API-v1.md) for the REST contract, scopes, idempotency, upload flow and webhook verification examples.

For local Google OIDC setup, create a non-production Google OAuth web client and register `http://localhost:3000/api/auth/callback/google` as its authorized redirect URI. Put its client ID and secret in the ignored `.env.local`. The login flow requests only `openid`, `email`, and `profile`; no Drive or other Google scopes. Real Google callback acceptance is still open until non-production credentials are supplied and browser tests pass.

## Architecture boundary

Shared TypeScript packages own domain behavior, contracts, job and payment rules, security policy, and Worker Protocol semantics. Netsons and AWS contain only deployment composition and infrastructure adapters. The seller Worker is a separate host-native process and never executes paid work outside the required sandbox.

Paid Core execution remains fail-closed unless the exact M08 reservation, M09 eligibility, M07 lease, Worker readiness and approved sandbox all pass. The development-credit installed-Worker path passes locally; Stripe-backed staging, the full security matrix and both-provider release conformance remain open.
